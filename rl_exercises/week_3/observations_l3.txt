
We used the random walk example from the paper. The states are:

0, 1, 2, 3, 4, 5, 6

0 and 6 are terminal states
The episode starts in the middle at state 3.
The walker randomly goes left or right. If it ends at the left terminal the outcomeis 0, and if it ends at the right terminal the outcome is 1. So the values should
go up from left to right. 

The true values for states 1 to 5 are about:
0.1667, 0.3333, 0.5000, 0.6667, 0.8333

The update the normal TD error was used:

delta = reward + gamma * V(next_state) - V(state)

The eligibility trace is basically like memory of where the agent was recently.
When a TD error happens, the recent states also get updated, not only the current one.
Then the memory fades using gamma * lambda. So small lambda means shortmemory, and high lambda means longer memory.

We ran it for 100 episodes with alpha 0.1 and gamma 1.0.
We tried lambda values 0.0, 0.3, 0.8 and 1.0. The results are saved here:

results/td_lambda/random_walk/seed_0/lambda_results.csv

The RMSE values were:
lambda 0.0: 0.0359
lambda 0.3: 0.0581
lambda 0.8: 0.0645
lambda 1.0: 0.1404

lambda 0.0 was best. usually bigger lambda would always help more, but it does not seem the case. With this alpha and only 100 episodes, lambda 1.0 was worse. The values still
mostly have the right shape though, going bigger from left to right.

Compared to the paper, this is only a small version. We did not repeat the full experiment many times or tune alpha for every lambda. But it shows the same basic point from the paper: TD(lambda) changes how credit is spread backward
through recent states, and different lambda values can learn differently.
